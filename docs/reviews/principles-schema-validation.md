# Shared principles schema validation

Validation completed on 2026-09-13 for the `schema-alignment` working tree.
This review maps the shared-schema change to observable behavior, rather than treating a
passing suite or a coverage percentage as proof of correctness.

## Findings repaired

1. **Promotion requirements accepted malformed arrays.** The runtime compared comma-joined
   arrays, accepting a single comma-separated value or nested arrays that JSON Schema rejected.
   It now compares the exact length and each typed value.
2. **Schema and runtime disagreed on blank descriptions.** Whitespace-only protocol descriptions,
   titles, categories, and measures could pass the published schema but fail the runtime. The
   schema now requires non-whitespace text wherever the runtime requires it.
3. **Rollback failure hid migration recovery state.** A failed restoration could throw away the
   structured result. Migration now reports each file requiring recovery, retains backup paths,
   and does not claim that unrecovered replacements were restored.
4. **Already-converted catalogs were not rechecked before other files were replaced.** Migration
   now checks every observed catalog again after staging. Simulated concurrent edits prevent
   committing other conversions; edits discovered during rollback are preserved and reported.
5. **Old schema files could accidentally return to the package.** Build now rejects obsolete
   schema sources and requires the shared schema. Package tests check actual exported paths and
   the exact three-schema inventory.

The first two findings concern graph protocol validation. Migration recovery protects
repository-owned structural context. None promotes engineering advice to a binding rule.

## Coverage of the intended change

| Requirement | Evidence |
|---|---|
| One shared schema, strict family authority | Ajv validates all three families, including populated P entries. The generated field corpus rejects 6,719 schema-invalid type, missing-key, unknown-key, and array mutations at runtime. |
| Semantic enforcement remains stronger than document shape | Registered detector identity, group ownership, P enforcement coverage, and unknown references are checked independently. |
| A global, P scoped, E advisory | After migration, A resolves on root and sibling contracts; P resolves only on the selected module; E is absent from binding context and cannot enter enforcement. |
| Preserve authored meaning | Frozen legacy YAML fixtures are independent of the new format. Every statement, ID, reason, cost, group, category, protocol field, and detector payload is compared after conversion. Comments and folded scalar content also survive. |
| Explicit migration and no silent rewriting | Preview, missing rationale, invalid input, mixed versions, invalid already-converted catalogs, idempotence, and re-init preservation are exercised. |
| Safe failure handling | Injected backup, replacement, restoration, and concurrent-edit failures assert original bytes, backup contents, recovery reporting, and preservation of concurrent edits. |
| Actual distributable works | A test packs and extracts the tarball, supplies only its runtime dependency, deletes the copied source/build directories, resolves public exports, then runs init, migration, verify, sync check, and repeat migration. |
| No old-schema fallback | The extracted package contains exactly principles, contract, and enforcement schemas. Poisoned legacy schemas in an adopter are ignored; deleting them still passes verification. |
| Contract/enforcement and repository policy preserved | Migration and re-init compare authored contract, enforcement, workflow, and phase-policy bytes. No schema consolidation rewrites those files. |

The previous migration fixture was generated by reversing the new format. Frozen historical
architecture input and independently authored E/P examples now avoid that correlated-test risk.
The package test also declares an independent consumer package so Node's package self-reference
cannot silently resolve exports from the source fixture.

Primary tests: `test/principles.test.js`, `test/build.test.js`, and the retained graph/verifier
regressions in `test/contracts.test.js` and `test/verify.test.js`.

  disable authority checks, rationale validation, promotion shape checks, detector registration,

## Remaining limits

The adopting-repository trial still needs a repository path. Public hosting of the new schema
has not been verified by this audit; package tests validate the bundled schema without network
access. Publication must serve matching schema bytes at the canonical URL.

Migration is not a transaction across multiple filesystem files or a lock against other writers.
Exception recovery is tested, but a process crash or power loss can require recovery from the
retained backups. Tests verify P enforcement mappings; they do not prove that an arbitrary
repository detector string identifies a working build-blocking test. These limits preclude a
blanket claim that nothing can break in every adopting repository.
