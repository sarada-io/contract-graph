# Manuals

Instructions for people using the product: what they can do and how to do it. For a game,
this includes how to play, game rules, player controls and tutorials. Other examples include
customer onboarding and instructions for completing a business task in the application.

Describe the supported experience today, in the reader's language. Include prerequisites,
actions, expected results and help for common problems where useful. Do not require development
commands or knowledge of the framework merely to use the product.

Technical instructions for building, deploying, releasing, operating or maintaining the software
belong in `../guides/`. Classify by audience and purpose, not the document title: a “player guide”
belongs here; a “deployment manual” belongs in guides. Keep one canonical document per reader
need. Link shared facts rather than copying them, and update or retire instructions when the
supported product changes. Create substantive manuals only when a reader needs them.
